# shortvideo-script-doctor

AI 生成短视频/长视频的**脚本诊断与改造**工具。给它一条脚本，它还你一份打分、一份改动清单、一份能直接开工的分镜表。

## 这是什么

大部分"爆款方法论"只管写，不管验。这个工具反过来：**先判定这条片子能不能发，再决定改什么、改多少。**

三条立场决定了它的所有行为：

1. **钩子是承诺，素材是兑现。** 没有素材撑住的钩子，第 8 秒一定塌，完播率反而更差。
2. **规则用来判定，不用来把分数做好看。** 第 5 项（8 秒兑现）和第 6 项（证据位）任一为 0，直接退回重写，不进入逐句修改。
3. **不搬过期话术。** 网感写在人群层（怕什么、羞于承认什么），不写形式层（梗、语气词）。

## 边界（重要）

**下游固定为 AI 生成，不是实拍。** 这条决定了几件事：

- 证据位不能用"真实顾客反应"——AI 造不出来，造了就是虚构事实
- 画面描述要细到能直接喂模型
- 生成备注是必填项，不是可选
- 数据、参数、价格一律走后期字幕，不写进画面

**适用：**

| 维度 | 范围 |
| --- | --- |
| 时长 | 15 秒 – 3 分钟（分 S/M/L 三档，各用不同检查表） |
| 场景 | 信息流为主：探店、产品片、AI 短剧、口播 |
| 目标 | 完播、转发、信任，不承诺转化 |

**不适用 / 减配：**

- 教程类、知识付费 → 减配（不评钩子，观众是来查信息的）
- 品牌形象片 → 减配（不评目的单一和收口三件套）
- 纯产品展示、无叙事素材 → 先解决素材问题，改脚本是空转
- B2B 工业品、招商留资 → **超出范围**，慢决策场景需要另一套逻辑

## 安装

```bash
# 放到你的 skills 目录
cp -r shortvideo-script-doctor ~/.workbuddy/skills/
# 或 ~/.claude/skills/ 、你的 agent 的 skills 目录
```

装好后用 `/shortvideo-script-doctor` 触发，或直接说"按规则改一下这条脚本"。

## 怎么用

给它任何形式的脚本：分镜表、口播稿、docx、截图、直接粘贴的一段话。它会走七步：

```
0 读稿 → 1 判档与诊断 → 2 定目的 → 3 盘素材（含 AI 可做性）
→ 4 重排结构 → 4.5 时长核算 → 5 改台词 → 6 收口与物料 → 7 交付
```

**交付八项**，顺序固定：诊断 / 改动清单 / 改后分镜 / 镜头级对照 / 配套物料（标题3版+封面+置顶评论）/ 待确认项 / 原稿保留部分 / **干净版分镜表**。

最后一项是唯一给下游的——不带诊断和理由，只有镜号、时长、画面、台词、字幕、音效、生成备注。生成环节照着这张表逐镜编译提示词。

## 两套检查表

| 档位 | 时长 | 留人靠什么 | 用哪套 |
| --- | --- | --- | --- |
| **S** | ≤60s | 前 3 秒决定生死 | `scorecard.md` 十项 |
| **M** | 60–120s | 前 3 秒 + 中段二次钩子 | 十项，第 5 项改判"前 1/4 兑现" |
| **L** | >120s | 未完成感 | `scenes.md` 长视频十项 |

**先判档，再打分。** 判错档，60 秒以上的片子在第 5 项"8 秒兑现"上永远得 0，会被误判成必须重写。

## 目录

```
shortvideo-script-doctor/
├── SKILL.md                    主流程与硬规则 A/B/C/D
├── CHANGELOG.md                三个版本，三栏制（改了什么/为什么/没改什么）
├── references/
│   ├── scorecard.md            20 分自检卡（S/M 档）
│   ├── scenes.md               分档表、长视频四关口、二次钩子、完播曲线读法
│   ├── hooks.md                九钩归三引擎
│   ├── line-fixes.md           台词六种病与改法
│   ├── platform.md             平台规则可信度分级（A/B/C）
│   └── case-study.md           两个案例：结构塌陷（删）、证据缺失（补）
├── assets/
│   ├── storyboard-clean.md     干净版分镜表模板 + 下游映射
│   └── spec-example.json       对照图数据示例
└── scripts/
    └── compare_chart.py        改前改后分镜对照图（需要 Pillow ≥ 8.2）
```

## 可视化（可选）

```bash
pip install -U pillow
python scripts/compare_chart.py assets/spec-example.json out.png
```

生成一张左右对照图，色块长度即镜头时长，一眼看出删了哪几镜、证据位前移了多少。

## 它不做什么

- 不替商家编造利益点、价格、名额——没有就标 ⬜，让商家填
- 不把原稿的专业手法一起改掉（AI 规避、镜头语言、音效设计属于"不该动的部分"）
- 不为了让分数好看硬凑——够不着就写"受素材限制只能到 1 分"
- 不承诺效果——只会判断"能不能发"，不会承诺"会不会爆"

## 设计原则

**分数天花板不在改法上，在素材上。** 两个真实案例：一条 6 分改到 18 分（靠删），一条 16 分仍被退回（第 6 项证据为 0，靠补）。把天花板写进交付文档，比把分数刷到 20 分有用。
