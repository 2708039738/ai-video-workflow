# 单镜实验报告模板

> 用途：一次局部替换/单镜重生成做完后，用这份格式交回来。
> 一份报告只讲**一个镜头**。做了三个片段就交三份，不要合并。

## 接入 skill（给 Claude 看）

报告是模式 C 的"实际结果"输入，也是 `lessons-log.md` 候选经验的证据来源。一份报告可提炼 0–3 条候选，用户回复"记"才入库。

| 报告字段 | 对应经验库字段 |
|---|---|
| 一、目标通道 / 跑了几次 | 平台 / 模型 / 入口；证据等级。每轮改了变量的多轮尝试不算同条件复现，默认记 `单次` |
| 二、结论 + 判据 | 结果 |
| 五、失败帧 + "你改了什么" | 现象、改动 |
| 六、可复用的规则 | 候选经验；默认状态"待验证假设" |
| 七、本机限制 | 不进经验规律；可记入 `platform-profiles.md` 对应条目，来源写"用户实测" |

没有判据或没有失败帧的报告，先请用户补，不据此提候选。

---

## 一、基本信息

| 项 | 内容 |
|---|---|
| 项目 / 镜号 | 例：某职业培训学校 · 结尾镜 S10 |
| 这一镜要修什么 | 例：结尾人脸与开头不是同一人 |
| 上游依据 | 脚本哪一行 / 分镜表哪一镜 |
| 目标通道 | 官方 API / 中转站 / App，写清哪个 |
| 跑了几次 | 例：6 次（5 次失败，1 次成功） |
| 花了多少 | 例：约 XX 积分 / XX 元 |
| 日期 | |

---

## 二、结论（三行，必须写）

```
目的：（这一镜要解决什么）
结论：□ 成了  □ 没成  □ 部分成（写出哪部分成、哪部分没成）
判据：（怎么判断的——并排看？找第三人看？）
```

**判据不能写"看着还行"。** 要写具体动作，例如"把开头镜最后一帧和新片段第一帧并排，看鼻梁高度和左眉形状是否一致"。

## 三、验收六条（逐条打勾，附证据图编号）

| # | 检查 | 结果 | 证据图 |
|---|---|---|---|
| 1 | 脸和相邻镜头是同一个人 | □过 □不过 | 图 __ |
| 2 | 接点前后 0.5 秒，色调/亮度无跳变 | □过 □不过 | 图 __ |
| 3 | 前一镜结尾姿态 = 新片段开头姿态 | □过 □不过 | 图 __ |
| 4 | 画质不劣于原片 | □过 □不过 | 图 __ |
| 5 | 音轨连续，接点无爆音 | □过 □不过 | 图 __ |
| 6 | 嘴型与音轨大致同步 | □过 □不过 | 图 __ |

这六条是为"修脸/接点"类单镜设计的默认项。本镜目的不同，就按目的增删（总条数照写，每条仍要证据）。常见替换项：

- 口播镜：台词在说话窗口内念完（语速按主文件"说话窗口"规则算，参考上限 6.5 字/秒）；真人出声念一遍不卡壳，卡壳处记下第几个字；字幕与台词逐字一致
- 产品/菜品镜：食物颜色、油光、蘸料挂壁是否真实；LOGO 与字幕文字是否正确（交后期的除外）

**任何一条不过，都要在第 5 节写清失败特征。**

## 四、画面（6–8 张，每张一句话说明）

只要这几种，不要整屏截图：

| 编号 | 要什么 | 用来证明 |
|---|---|---|
| 图 1 | **首帧原图**（输入） | 起点是什么 |
| 图 2 | 新片段**第 1 秒** | 动起来了 |
| 图 3 | 新片段**中间** | 手势/表情到位 |
| 图 4 | 新片段**最后一帧** | 收尾姿态 |
| 图 5 | **接点前 / 接点 / 接点后** 三帧拼一张 | 调色有没有跳 |
| 图 6 | **原片开头人脸 vs 新片段人脸** 并排 | 是不是同一个人 |
| 图 7 | 原片相邻镜头 vs 新片段，同尺寸并排 | 画质有没有劣化 |

每张图下面写一句：`图 X：证明____，结论____`

**图 6 是最重要的一张。** 这一镜的目的就是修脸，看不懂这张等于没交。

## 五、失败帧（1–3 张，必须有）

**只交成功案例的报告没有价值。** 失败帧才是"这个通道能做什么、不能做什么"的证据。

| 编号 | 第几轮 | 失败特征（用画面说） | 你改了什么 |
|---|---|---|---|
| 图 F1 | 第 __ 轮 | 例：双手在腹前合拢，读成"两手一摊" | 加了几何参数 |
| 图 F2 | | | |

写清失败特征的**具体位置**，例如"两只手在腹部前方相距约 10 厘米"，不要写"手势不对"。

---

## 六、可复用的规则（3–5 条，这是最值钱的部分）

写成"因为 X，所以要 Y"的句式，不要写"注意手势"这种正确的废话。

单镜单次得出的规则，默认只是 `待验证假设`：相同条件下至少两次方向一致的复现并经用户确认，才可升为"已确认规律"。每条写明适用范围（平台 / 模型 / 镜头类型）。

示例：

- 因为"摊开"在模型里对应至少三种动作，所以必须给几何参数（高度/宽度/角度），不能只给形容词。
- 因为含"双手一起"语义的词（捧、托、合）都会让两只手并拢，所以比喻要慎用。

**每条后面标证据**：`（图 F1 验证）`

---

## 七、本机限制（不可复用的部分）

这一节单独隔开，因为它换台机器就不成立。

| 限制 | 报错原文 |
|---|---|
| 例：不接受首帧 + 参考图同时输入 | `model xxx does not allow ...` |

---

## 八、下一步

```
如果继续：改哪一处，预期什么变化
如果不继续：为什么，卡在哪
```
