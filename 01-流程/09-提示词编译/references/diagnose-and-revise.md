# 模式 C:结果 → 诊断修改

用户贴来"提示词 + 生成结果 + 与预期的差距"时使用。目标:让下一次生成更接近预期,并留下可复用的经验。

## 需要的输入

- 原提示词(完整,含参考图说明)
- 平台/模型/入口,以及关键参数(时长、画幅、是否用了参考图/首帧)
- 生成结果:截图、视频的文字描述(按时间顺序说发生了什么)
- 预期:想要的画面/动作/感觉。最好给到"哪一秒哪里不对"

缺关键信息时只问最必要的一两项。结果是视频但用户只给了总体感受("不对劲"),请对方按时间点说一两处最明显的偏差,而不是替用户猜。

## 流程

### 1. 差异对齐

把"预期"和"实际"逐项列成表,不要直接动提示词。偏差程度按后果判,不按观感判:

- **重** = 主体身份变了、故事顺序错了、台词少了字、画面里出现不该有的人或物;必须改,改完重跑。
- **轻** = 主体与叙事都对,只是构图偏一点、光线冷一度、动作幅度小一点;记下来,下一轮顺手调。
- **无** = 与预期一致。

| 维度 | 预期 | 实际 | 偏差程度 |
|---|---|---|---|
| 主体身份 | | | 无 / 轻 / 重 |
| 动作与顺序 | | | |
| 构图/景别/首帧 | | | |
| 镜头运动 | | | |
| 光线与色彩 | | | |
| 风格与质感 | | | |
| 细节(手、文字、道具) | | | |
| 时长与节奏 | | | |
| 声音/口型 | | | |
| 连续性(与前后镜) | | | |

只列有偏差的行。偏差说不出来的,标 `待补:结果与预期的具体差异`。

### 2. 定位原因(假设)

对每个偏差,在提示词里找对应片段,判断属于哪类问题:

- **缺失**:提示词根本没写这件事,模型自由发挥
- **冲突**:提示词内两处要求互相矛盾(例如"静止机位"又写"推近")
- **过载**:一个镜头塞了多个动作或多种镜头运动
- **含糊**:用了抽象词,没有可观察描述
- **优先级错位**:关键要求埋在长句末尾,或被大量风格词淹没
- **参考管得太多/太少**:参考图把不该继承的属性也带进来,或职责没写清
- **能力边界**:该需求超出平台/模型当前能力,改提示词收益有限

原因一律写成**假设**,按可能性排序。不得说"一定是因为"。可以说"最可能是 X,次可能是 Y"。

### 3. 失败类型速查

下表是**常见假设与改法**,不是定论,不同平台表现不同。平台特有的现象以 `lessons-log.md` 中经实测的条目为准。

| 现象 | 常见假设 | 可尝试的提示词改法 | 提示词之外的路线 |
|---|---|---|---|
| 角色脸/服装前后不一致 | 锚点没重复;参考图职责不清 | 每镜重复身份与服装锚点;写明参考图只管面部 | 先出角色设定图再图生视频;缩短单镜时长 |
| 动作没发生/发生错 | 动作含糊或过多 | 写成起→中→终的可见序列,一镜一动作 | 拆成两个镜头 |
| 手、手指、握物变形 | 手部动作复杂 | 简化手部动作;换成不显手的构图 | 景别避开手;实拍/后期替代 |
| 镜头运动不对 | 多个运动并存或描述含糊 | 只写一种运动,方向与幅度写明;或写固定机位 | 后期做推拉 |
| 构图偏离首帧 | 首帧要求没写位置与余量 | 补主体位置、视线、前中后景 | 用图生视频/首帧锁定(平台支持时) |
| 文字乱码/错字 | 模型不擅长精确文字 | 画面内不要求精确文字,预留位置 | 文字交后期叠加 |
| 口型对不上/台词被吞 | 台词过长或音画同生成不稳 | 缩短单镜台词;分句分镜 | 数字人/配音+口型驱动;后期配音 |
| 风格飘、质感不对 | 只有抽象词 | 换成光源、材质、色温、对比度的可见描述 | 提供参考图,写明只继承风格 |
| 光线色彩跳变 | 光线没写或前后镜不一致 | 每镜重复光源方向与色温 | 后期调色统一 |
| 多人互动崩坏 | 复杂交互超出能力 | 拆成正反打、手部、单人镜头 | 实拍或分别生成后合成 |
| 参考图元素乱入 | 参考图职责不清 | 写明"只继承 X,不继承背景/服装/光线" | 裁剪或抠图后再作参考 |
| 动作太快/太慢/节奏怪 | 时长与动作量不匹配 | 减少动作或延长时长;写明速度 | 剪辑变速 |
| 物理不合理(穿模、液体、布料) | 复杂物理超出能力 | 简化物理过程 | 换角度回避;后期合成 |

### 4. 改写规则

- **每轮只改 1–3 处**。同时改太多,下一轮无法判断是哪处起了作用。
- 先改"缺失、冲突、过载",再改"含糊",最后才考虑堆砌新词。
- 不用加大量强调词(例如反复"一定要""非常")当修复手段。要强调,改变信息的位置和具体程度。
- 保持来源事实不变(台词、品牌信息、故事顺序),不为了迁就模型而改剧情。
- 认为需要改路线时,明说原因和代价(时间、成本、风格一致性),让用户决定。

### 5. 版本编号与修改履历

- 每个镜头的提示词版本使用 `镜头号-v版本`，例如 `3-v2`。
- 拆分镜头沿用拆分号，例如原镜头 3 拆为 3A、3B，修订版分别为 `3A-v2`、`3B-v2`；不得改成与原镜头无关的编号。
- 每轮提供当前版本的完整可复制提示词，并附该镜头的履历表。首次交付记为 v1；后续只列最新版本全文，不重复粘贴旧版，除非用户要求比较或回退。
- 没有真实生成结果时，履历结果写 `待核实:尚无本版生成结果`；预测效果不可写成实测结果。

| 镜头/提示词版本 | 改了什么 | 想改善什么 | 实测结果 |
|---|---|---|---|
| 3-v2 | 将“拿起杯子”拆成抬手、握杯、端至胸前 | 减少动作歧义 | `待核实:尚无本版生成结果` |

拆分镜头示例：`3A-v2` 的履历只追踪 3A；若 3B 也修改，另列 `3B-v2`，不可把两者结果混记。

### 6. 交付格式

```
## 差异对齐
(表)

## 原因假设(按可能性排序)
1. 假设:... 依据:提示词中的 <片段>
2. ...

## 提示词 <镜头号>-v<N>
(完整可复制)

## 变更说明
| 改动 | 为什么 | 预期改善 | 风险 |
|---|---|---|---|

## 下一轮请回报
- 重点看哪几点(时间点/元素)
- 若仍不对,备选方案:...

## 可入经验库的候选(首轮省略;用户回报改动后的实际结果后再附)
- ...
```

### 7. 下一轮

用户回报新结果后,先判断**上一轮的假设对不对**:改善了,说明假设可能成立;没变化,说明假设可能不对;更糟,回看改动是否引入冲突。再继续对齐、改写。连续两轮没有进展,建议换路线而不是继续微调。

### 8. 经验入库

只有用户提供了实际生成结果,才可写入经验库。流程:

1. 总结为一条:平台/模型、场景类型、现象、原提示词片段、改动、结果
2. 标证据等级:`单次` 或 `多次复现`
3. 整理成 `references/lessons-log.md` 的候选经验格式，注明证据标签；候选不等于已入库。
4. 用户回复“记”后，才写入经验库的“待验证假设”区。相同条件下至少两次方向一致的复现并经用户确认后，才可提升到经验库自己的“已确认规律”状态；这两个名称不是证据标签。
