# 问题记录模板

> 六行，不要多写。**先记卡在哪，不要先写解决方案。**

---

```markdown
- 日期：
- 卡在哪一步（节点号 / 门）：
- 我当时想做什么：
- 发生了什么：
- 我怎么绕过的：
- 我认为该改的是：
```

---

## 填写说明

| 行 | 怎么写 | 反例 |
|---|---|---|
| 卡在哪一步 | 写节点号，如 `09-提示词编译`，或门号 `门2` | 「流程不太顺」 |
| 我当时想做什么 | 具体动作，如「想把 21 镜拆成可提交的提示词」 | 「想优化一下」 |
| 发生了什么 | 客观描述，可截图、可贴报错 | 「感觉不对」 |
| 我怎么绕过的 | 实际做了什么（哪怕很土） | 「换了个方法」 |
| 我认为该改的是 | 一句话，可以不确定 | 「建议全面优化文档」 |

**为什么禁止一开始写建议**：学生会写「建议优化文档结构」，这种话改不了任何东西。要的是当时的动作和卡点。

---

## 三种不该记的

| 情况 | 为什么 | 该去哪 |
|---|---|---|
| 「我觉得这样更好」 | 个人偏好，不是卡点 | 不用记 |
| 「某某文档写错了」 | 是事实错误，直接改 | 提 PR |
| 「客户太麻烦」 | 不是流程问题 | 不用记 |

---

## 记录之后会怎样

| 情况 | 处理 |
|---|---|
| 1 个人遇到 | 记录，标注「个案」，不改母版 |
| 2 个人遇到 | 标「疑似」，观察 |
| **3 个人遇到** | **改母版** |
| 造成返工 > 1 小时 | 立即改 |
| 造成交付失败 | 立即改 |
